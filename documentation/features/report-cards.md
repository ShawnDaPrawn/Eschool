# Academic report cards

Report cards use the school's academic plans and immutable mark snapshots. A
school chooses a design, generic comment banks, a reporting period and an explicit
learner batch. Preview the evidence before preparing it. An incomplete learner
can wait while other learners progress; a running report must be explicitly
chosen and is visibly labelled provisional. Ungraded, excused and absent results
show their status without a made-up percentage.

Subject and homeroom teachers enter their comments in their allocated scopes.
A grade head signs first, then the principal. PDF generation runs in the queue;
preview the generated report before the school releases the batch and queues
family notifications. Any changed comment or refreshed evidence needs new
signatures. Stale edits must be compared before retrying.

Parents and learners receive only their own released reports. Downloads use a
short-lived authenticated link; reopen the list if it expires. A copied link
does not grant another account access. Earlier releases remain unchanged when a
new version is issued. Fees never withhold a report, and reporting never activates
an unapproved learner account. Guardians can retain report access for a disabled
learner account while their own guardian relationship remains active.

The service/API slice is implemented; the shared app and panel report screens are
being completed separately. Actual parent delivery, device checks and the pilot's
full-term evidence remain acceptance work.
