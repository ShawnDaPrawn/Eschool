The `documentation/` folder is a Docusaurus 3 site with the end-user documentation (installation, admin settings, mobile app setup, feature guides). It is published at https://shawndaprawn.github.io/Eschool/. This page explains how the site is built, how it is organised, how to run and deploy it, and lists every page with its published URL. For how the code works, use this wiki; for click-by-click instructions, link to the documentation site.

## Site configuration

[docusaurus.config.js](https://github.com/ShawnDaPrawn/Eschool/blob/main/documentation/docusaurus.config.js) sets:

| Key | Value | Effect |
|---|---|---|
| `url` | `https://shawndaprawn.github.io` | Production host |
| `baseUrl` | `/Eschool/` | Every page lives under `/Eschool/` |
| `organizationName` / `projectName` | `ShawnDaPrawn` / `Eschool` | Used by `docusaurus deploy` to find the repository |
| `deploymentBranch` | `gh-pages` | Branch `npm run deploy` pushes the built site to |
| `trailingSlash` | `true` | Every URL ends with `/` (pages are emitted as `<page>/index.html`) |
| `onBrokenLinks` | `'throw'` | A broken internal link fails the build (CI relies on this) |
| `onBrokenMarkdownLinks` | `'warn'` | Broken Markdown file links only warn. Docusaurus 3.10 prints a deprecation warning for this option on every build. |
| `i18n` | `en` only | No translations of the docs |
| `presets` | `classic` with `docs: false`, `blog: false`, `theme.customCss: ./src/css/custom.css` | The preset's default docs instance is off; all docs come from the plugin instances below |
| `stylesheets` | Font Awesome 6.5.1 from cdnjs | Icons used on the home page |
| `themes` | `docusaurus-search-local` with `hashed: true`, indexing `mobile-app`, `admin-panel`, `web-page` and `features` | Adds the search box and a `/search/` page. Support, FAQs and Changelog are not indexed. |

The footer copyright reads "Your Company", and the Support page and the home-page banner (`src/components/DocBanner/DocBanner.jsx`) use `support@example.com`. These are placeholders to replace with the school's or maintainer's details.

### Docs plugin instances

Each top-level section is its own `@docusaurus/plugin-content-docs` instance. The navbar has one entry per instance, in this order, plus the search box on the right.

| Plugin `id` | Folder (`path`) | `routeBasePath` | Sidebar | Navbar label |
|---|---|---|---|---|
| `mobile-app` | `mobile-app/` | `mobile-app` | `sidebars/mobile-app.js` (`mobileAppSidebar`, autogenerated from the folder) | Mobile App |
| `admin-panel` | `admin-panel/` | `admin-panel` | `sidebars/admin-panel.js` (`adminPanelSidebar`, autogenerated) | Admin Panel |
| `web-page` | `web-page/` | `web-page` | `sidebars/web-page.js` (`webPageSidebar`, autogenerated) | Web Pages |
| `features` | `features/` | `features` | `sidebars/features.js` (`featuresSidebar`, autogenerated) | Features |
| `support` | `support/` | `support` | none (`sidebarItemsGenerator` returns `[]`) | Support (links to doc `index`) |
| `faqs` | `faqs/` | `faqs` | none | FAQs (links to doc `index`) |
| `changelog` | `changelog/` | `changelog` | none | Changelog (links to doc `index`) |

Each file in `sidebars/` exports one autogenerated sidebar (`[{ type: 'autogenerated', dirName: '.' }]`). Order inside a sidebar comes from each page's `sidebar_position` front matter.

| `src/css/custom.css` | Global theme overrides |
| `static/images/admin/`, `static/images/app/`, `static/images/web/`, `static/images/logo/` | Screenshots for the admin panel, mobile app and website pages, and the logos (`logo/logo.png` is the favicon, `logo/transparent_logo.svg` the navbar logo and social card) |

Pages reference screenshots with a relative path from the Markdown file, for example `![Session Year](../static/images/admin/7.png)`; Docusaurus resolves and bundles them at build time. A few feature pages embed YouTube videos with a raw `<iframe>`.

## URL rules

- A page's URL is `https://shawndaprawn.github.io/Eschool/<routeBasePath>/<file name without .md>/`.
- `index.md` maps to the section root, e.g. `admin-panel/index.md` is `/Eschool/admin-panel/`.
- No page sets `slug:`, `id:` or `sidebar_label:` front matter, so file names are the slugs and the first `#` heading is the page title (`changelog/index.md` also sets `title: Changelog`).
- `trailingSlash: true` means links should always end with `/`.

## Running locally

```bash
cd documentation
npm ci            # installs exactly what package-lock.json lists (README says npm i; ci is what CI runs)
npm start         # dev server at http://localhost:3000/Eschool/
```

To check a change the way CI does, build it; the build fails on any broken internal link:

```bash
cd documentation
npm run build     # output in documentation/build/
npm run serve     # optional: serve the built site at http://localhost:3000/Eschool/
```

A clean build prints two expected warnings: the `onBrokenMarkdownLinks` deprecation and ``Warn: `blogDir` doesn't exist`` (the search plugin looks for a blog folder; there is none).

## Deployment to GitHub Pages

The configuration targets GitHub Pages: `url` + `baseUrl` give https://shawndaprawn.github.io/Eschool/ and `deploymentBranch` is `gh-pages`.

No GitHub Actions workflow deploys the site. [ci.yml](https://github.com/ShawnDaPrawn/Eschool/blob/main/.github/workflows/ci.yml) only builds it (job `docs`, see [Testing-and-CI](Testing-and-CI#docs-documentation-build)), and [wiki.yml](https://github.com/ShawnDaPrawn/Eschool/blob/main/.github/workflows/wiki.yml) publishes this wiki, not the docs. When this page was written the `origin` remote had no `gh-pages` branch. Publishing is therefore a manual step run by a maintainer with push access:

```bash
cd documentation
npm ci
GIT_USER=<github-username> npm run deploy   # HTTPS: prompts for a token as the password
# or, with an SSH key set up for GitHub:
USE_SSH=true npm run deploy
```

`docusaurus deploy` builds the site, then commits the contents of `build/` to the `gh-pages` branch of `ShawnDaPrawn/Eschool` and pushes it. In the repository settings, GitHub Pages must be set to serve from the `gh-pages` branch (root folder).

## Deployment to Firebase Hosting

[firebase.json](https://github.com/ShawnDaPrawn/Eschool/blob/main/firebase.json) publishes the same site to Firebase Hosting on project `navigateed-d8c06` (see [.firebaserc](https://github.com/ShawnDaPrawn/Eschool/blob/main/.firebaserc)). The `predeploy` hook installs `documentation/` and runs `npm run build:firebase`, which sets `DOCS_BASE_URL=/` and `DOCS_URL=https://$GCLOUD_PROJECT.web.app`. The Firebase copy is served from `/` while GitHub Pages stays at `/Eschool/`. The public URL is https://navigateed-d8c06.web.app/. Hosting is the free Spark tier; this does not put the admin panel on Cloud Run. The env assignment lives in the npm script because the Firebase CLI drops a `predeploy` command that contains `=`. The site is the `docs` Hosting target, beside the `app` and `teach` targets of the web apps ([Building-and-Releasing-Apps](Building-and-Releasing-Apps#hosting)); `firebase deploy --only hosting:docs` deploys it alone.

## Adding or changing a page

1. Create `documentation/<section>/<page-name>.md`, where `<section>` is one of `mobile-app`, `admin-panel`, `web-page` or `features`. Use lower-case, hyphenated file names; the file name becomes the URL slug.
2. Start it with front matter that places it in the sidebar, then a single `#` title:

   ```markdown
   ---
   sidebar_position: 12
   ---

   # Page Title

   Text...

   ![Screenshot description](../static/images/admin/my-screenshot.png)
   ```

3. Put screenshots in the matching `static/images/<area>/` folder and reference them with a relative `../static/images/...` path.
4. Link to other pages with relative Markdown file links (`[Fee payment](./fee-payment.md)`) or root-relative URLs with a trailing slash (`/admin-panel/fee-payment/`). `baseUrl` is added automatically.
5. Run `npm run build` and fix any broken-link error before opening a pull request.

Support, FAQs and Changelog are single `index.md` pages with no sidebar; edit those files directly. A new top-level section needs a new plugin instance in `docusaurus.config.js`, a sidebar file, a navbar item, and (for search) an entry in the search theme's `docsRouteBasePath` and `docsDir` lists.
