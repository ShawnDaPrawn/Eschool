# Community, Home, Settings and account implementation

Revision 3 is implemented in the existing Laravel panel and Material 3 components. `community-home-settings-trace.json` maps 392 design/state IDs to concrete views, URL states, state rendering and owners; 301 are owned here, including the complete staff re-enrolment family and the transferred assistance office workspaces. Shared navigation, school/year context, readiness, personal notifications and HTTP recovery have explicit transferred owners. This record does not claim a private Build Bible acceptance gate or production rollout.

## Workspaces and source behaviour

- School Home retains live school/teacher/staff widgets and the actual setup checklist, with permission-filtered operations links. It does not render the HQ dashboard as the school workspace. Emergency alerts, prepare/send/all-clear, roll-call, reunification, visitor sign-in/out, drills, retained history and retention settings have separate URL states. Meeting slots, collection approval/revocation and collection rules also have separate states.
- Community messages separates the directory/review queue, editor, saved audiences, smart groups and author rules. All existing revision, audience fingerprint, private draft restoration, non-author approval, scheduling, withdrawal, delivery-report and family-reach contracts remain in use. Notices have a native directory and separate create/edit screen. Audience controls preserve multiple-target creation and the saved allocation/term, existing attachments remain readable, and new attachments stay available for every audience type. Teacher writes validate current owned allocations; school staff can manage whole-class and noticeboard records. Notifications separate composing/recipient selection from history.
- Newsletter has a real repeatable section editor. Add/remove/reorder sections compiles the content to the existing persisted message Markdown, and users review the saved content and actual audience before submitting through the existing approval/delivery workflow. It is one school message, with no invented edition table or fabricated delivery receipts. Weekly digest language versions and approval/withdrawal are separate from newsletter composition.
- Private gallery separates group photographs, upload and consent configuration. Source image access, private groups, tag proposals, guardian approval rules, actor/school pins, sanitisation and withdrawal remain enforced. Consultation directories, draft questions, frozen publication, eligible ballots, configuration history, live aggregates and closed named/anonymous results retain their distinct source states.
- Calendar events use native labelled date/time controls and real repeatable programme rows. Parent/child changes validate as one transaction; a wrong-parent row or invalid later row cannot partly update the event. Programme changes and saved-row deletion are persisted and reloadable. Add/remove actions are disabled and guarded while the programme save is pending, with their prior disabled states preserved. Calendar-event deletion uses Material confirmation and refreshes its actual directory.
- CO028 adds explicit calendar-event associations to existing consent requests and admission events, plus encrypted office transport notes. The form binds actor, school and revision. Every linked consent read reuses current managed-group authority; every admission read reuses ticket-management authority. Composite school foreign keys reject cross-school links. Admission choices have a scoped name search and 25-record pages so older records remain reachable. Counts distinguish total participants from effective/not-cleared recipients on the current page; no inferred participant roster or guardian response submission is added. Links/notes must be cleared before deleting the calendar event; consent/admission source records remain intact.
- School settings has six independent save sections: school, branding, localization, links, policies and security. Each section validates only its own fields and preserves unrelated settings. Active school year is read-only with a global management link. Blank stored secret retains its current value and secrets are not reflected. A seventh, Super Admin-only Maintenance tab retains the existing shared-cache POST with CSRF, year-safe status and explicit confirmation; the global header no longer carries that action. School documents, support ticket creation, reader registration and module/role operations use dedicated views or record workspaces. The assistance office separates its queue, assigned conversation/review, approved document directory and document/version publisher. Private invalid drafts stay in their own editor without session flash; thread actions and document withdrawal stay with the selected record.
- The standalone M3 account shell covers login, reset request, reset completion, invalid/expired token, password confirmation and verification. Personal profile uses actual editable fields, and password forms disable persistent drafts. PR489 provider source is integrated by the root agent; provider settings/linked accounts are separate sections with source password confirmation and removal rules. Provider configuration is not enabled by this implementation.
- Staff re-enrolment now has a native contract directory, full-body publication form, immutable wording/hash workspace, outstanding household requirements, signed acceptance audit, scoped reminder batch receipts and withdrawal. It calls existing services, preserves the actual required guardian/fee-responsible rules, and does not submit guardian consent, promote learners or activate a school year. Private body is escaped, audit omits IP, and writes bind actor/school/revision with explicit confirmation.

The final save-destination audit found no stale handoff in these separated workspaces. Assistance publication/withdrawal retains the selected document in `view=documents`; school-information publication/unlisting returns to its document directory. Newsletter saves and private recovery preserve newsletter/compose context and the selected message; author-rule saves return to configuration, while audience saves retain the record and year. Gallery configuration returns to configuration, photo actions to the scoped photographs, and Digest creation/review to versions for approval. Programme saves retain the event ID; event saves intentionally return to the event directory. General Settings stays on its active section, Maintenance returns to its originating page, and public-website AJAX saves reload the current URL/view. No additional application change was needed for this audit.

## Limits and ownership

Admission sales, ticket types/counter, school subscription invoices and financial outcomes are owned by the Finance agent. Effective person/role access review is owned by People. Global year preparation/activation/cleanup and module readiness are owned by Navigation. Shared private refusal/recovery screens and personal inbox/preferences are owned by Root. Their traces carry their own verification evidence.

External email/push/provider delivery and real reader hardware are not activated or asserted by synthetic local tests. Gallery browser tests use a narrow local scanner fixture that accepts the exact synthetic image and its actual sanitized derivatives; they verify application upload/privacy behaviour, not malware detection. Production scanner behaviour is unchanged. New English label fallbacks are supplied in `community-home-settings-labels.json`; translation review remains distinct from source/UI verification. No owned implementation or local qualification is pending. External checks above and the shared integration/CI/release process remain separate. There is no production deployment in this work.
