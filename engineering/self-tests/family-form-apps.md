# Family consent and Health app readers

The Parent app reads one current approved child's activity requests, displays the
immutable wording and school-local times, and records an explicit account-name
attestation. An uncertain response retains the same operation UUID for an exact
retry. Operational Teacher and Facilitator readers show effective permission
separately from a retained previous answer; these readers grant no family Health
access. Staff publish immutable requests from the responsive staff workbench.

The Health editor reuses the dynamic encrypted profile schema behind the private
family-purpose API. It preserves false values, exact text and deliberate clears.
File reads ignore attachment URLs and use the current scoped binary endpoint.
Private images use an owned codec/RawImage with byte zeroization and image disposal,
without global ImageCache entries. Nested editors and file viewers are removed on
background, identity/context refresh or fresh authorization refusal.

The native document chooser disposes the old medical editor before opening the
operating-system picker. It retains only person/field scope, bounds the chooser
handoff to 60 seconds and rechecks the child's current configuration, write access
and editable field before posting. Picker bytes are zeroized after use or refusal.
An unsaved editor must be saved before selecting a document.
