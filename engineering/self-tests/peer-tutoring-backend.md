# Peer tutoring backend and typed API qualification

The off-by-default `peer_tutoring` module depends on mastery. Current scoped
staff match approved, currently enrolled learners using published topic gaps and
evidenced tutor proficiency. A supervised session creates no mastery evidence.
Verified integer service minutes use an append-only ledger. Optional house points
reuse the existing policy, cap, event and reversal services in the same transaction.
No point policy, provider, production module or live school is activated.

## Executed locally

- Typed domain/global OpenAPI and tenancy cohort: 606 tests, 3,660 assertions.
- Expanded focused boundaries: 17 tests, 116 assertions, including nonscalar
  persona rejection and service correction after an independently reversed point.
- Actual HTTP covers current staff and own Parent reads, valid other-school
  account followed by guessed-record refusal, role-purpose borrowing, wrong
  account, and private writes refused in query parameters.
- Exact operation replay preserves one session/service/point effect; changed
  intent, stale revision, premature completion, invalid duration, unapproved or
  withdrawn learners, incorrect allocation and unrelated mastery are refused.
  Readonly cancellation remains available to the authorized supervisor.
- Real populated dependencies remain protected during rollback. The empty
  peer/Tutor/practice/mastery dependency roundtrip passes: 1 test, 7 assertions.
- Selected PHPStan: zero errors. Changed PHP passes Pint.
- All 172 shared API SDK tests pass, including six peer protocol tests covering
  school-local wall times, integer minutes, nullable private service, explicit
  readonly capability, persona/account/school binding and body-only mutations.
- Canonical API retains all previous 457 paths and 1,168 schemas, adding eight
  paths, nine operations and seventeen schemas. Generation repeated with
  identical hashes for 2,436 Dart files and their manifest (2,437 entries).

The staff panel, shared native staff/family workflows, context erasure and actual
browser journeys are subsequent work. This checkpoint is backend/API software
qualification, not complete peer tutoring or Phase 4 acceptance. Published-head
CI, staging, wording review, physical devices and production approval remain
separate evidence.
