# Source-aware progress notifications

The registered `progress.` provider filters notifications by their exact current alert, state revision, audience and generated destination before counts, rows or bodies are read. Staff require current teaching allocation or dated leadership; family readers require their own approved, released evidence and current guardian/learner authority. The shared execution-time private scope prevents a previously prepared builder from retaining withdrawn authority. Transport reuses the existing fresh progress-delivery policy; a forged link cannot redirect a private notice.

Verification: the new five progress visibility scenarios, ten generic private-scope scenarios and eight staff-inbox cases pass **23 tests, 206 assertions**. They cover prepared-query allocation/role/state withdrawal, forged sources/links, frozen released evidence, guardian withdrawal, wrong school, impersonation and platform identity. The existing progress-alert and consultation-notice cohort passed eighteen cases; its remaining queued-mail case initially encountered an old Docker-owned local log, then passed separately (**1 test, 4 assertions**) using isolated native test storage. No production email was sent. Changed-file Pint and complete configured PHPStan pass with no errors.

The dedicated staff inbox receives a generic progress entry, containing no learner names, marks, topic or clinical body. Opening the learning-progress destination in that profile is a separately qualified client follow-on. This increment does not implement discipline notices, MyGrade, tutor sessions or model qualification.
