# Dedicated vendor operators and counter collection

Increment12 provisions new dedicated Vendor identities from Money → Vendor
operators. Finance verifies the actual person and explicitly assigns each counter.
Append-only assignment revisions retain grants and revocations; an inactive,
deleted, unassigned or ended member cannot inherit staff or family authority.
Initial sign-in requires a changed temporary password and current policy consent
before a session is issued. Separate Vendor tokens/cookies cannot enter Teacher,
Finance, family or personal wallet endpoints, even if another role is later added.

The private panel is `/vendor-counter`; its name avoids the existing public vendor
asset directory. The dedicated native Vendor flavour bootstraps its own repository
without Teacher authentication or storage. Both show only freshly assigned school
counters and redacted original order receipts, with typed numbers or private order
QR input. No buyer identity, wallet identifier, bank instructions or reusable order
QR token appears in a vendor response. Lookup reviews goods; it does not hand over.

Collection shares the existing school lock and append-only original-order terminal
boundary. One explicit confirmation records one handover without additional money
or stock movements. Same-operation replay returns the original receipt and warns
against supplying goods again. A pending native collection persists only opaque
school/actor/counter and operation identity; resolution either recovers the original
committed outcome or permanently abandons an unknown operation before another
confirmation. Fresh role, assignment and module checks run before cached replies.

Read-only commerce retains authorised history but stops handover. Finance may
revoke an assignment while commerce is paused. Backgrounding clears private native
and browser views; resume rechecks current authority. Camera lookup uses direct
platform scanning with a typed fallback, without a remote script dependency.
Credentials and private reasons never enter session old-input, including domain
refusals. Logout remains possible after membership ends and preserves unrelated
app tokens. Password changes revoke earlier sessions as the existing policy requires.

Settlement reporting, ticketing and online card spending remain subsequent
increments13–15. No payment gateway, outside payout or production activation is
included. Physical camera/device and external acceptance evidence stay separate.
