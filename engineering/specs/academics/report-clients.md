# Shared academic report screens

Build Bible Phase 2, report cards and desktop screens. The existing report services
remain the only source of preparation, comment, sign-off and release rules.

Staff open Reports from Home or Settings. The adaptive shared hub lists current
allocated comments and authorized report history, with explicit year and paging
controls. School managers edit designs and generic subject/homeroom banks; leaders
select a period, design, explicit learners and official or provisional mode, then
preview before preparing. Batch review displays evidence, comments and signatures.
A current grade head signs before a current principal. Queued PDF progress can be
refreshed/retried; staff preview individual PDFs before reviewing release and
notifying all eligible families with one action. Released versions are read-only.
Current leadership can reach retained report history after a class/grade remap.

Each comment owns a revision. A failed request keeps the text and operation UUID;
a conflict requires comparison with the latest saved text and an explicit choice
to keep the draft or use saved content before another save. Unsaved comments need
a deliberate discard before leaving. Administrative corrections collect a private
reason. Design, preparation, comment and approval retries use stable operation
keys while the exact request is unchanged. Panel operations and their private
receipts commit together; fresh domain authority precedes cached replay.

Parents/learners open their own report history from Home or Settings. Lists retain
older pages and distinguish provisional reports. Opening a PDF renews an expiring
link through fresh own-child access, checks its school/card/origin/path and signed
query before sending credentials, and refuses redirects. PDF bytes stay in route
memory. School/child/account replacement disposes the route; resume refreshes
access. Saving a copy is explicit and rechecks access; the user is told that the
copy remains on the device. Reading is acknowledged only after authorized bytes
arrive. No family request fetches a staff roster or another child's report.

The panel offers native forms with M3 tokens, equivalent service checks and private
signed PDF previews. Its report routes deliberately allow explicit historical
report operations despite the legacy header's general read-only-year banner;
current leadership, approval order and revisions still apply. Conflict pages keep
the submitted text and require an explicit reviewed-draft step before saving.
The report feature flag advertises completed clients, never grants authorization.

Verification: service tests for native forms, private redirects/replay, wrong
role/school/owner and revoked allocation; repository/cubit tests for URL validation,
private bytes, paging, transport/revocation and response ordering; widget tests at
390/1024/1280 and large text; both apps' actual sign-in/navigation Chrome flows,
including PDF rendering; native CI flows; panel Playwright at 1024/1280 with axe,
overflow and console checks. Physical phones, parent delivery receipts and pilot
acceptance remain external evidence rather than fixture claims.
