# Phase 4 decisions and open evidence

- Keep the existing teacher application identity and default commands. Reserve
  tech.tokensoft.navigateed.facilitator and tech.tokensoft.navigateed.vendor as
  proposed distinct native IDs, pending operator/store registration. These are
  neither registered nor released by source configuration alone.
- Facilitator/vendor builds stay unavailable before any teacher bootstrap until
  scoped roles, owned groups, menu and API exist. Build FLAVOR never grants roles.
- No outside provider receives Teacher or Super Admin permissions as a shortcut.
  Staff access remains fresh and school-scoped; an app build is not authority.
- Counsellor scope and anonymous escalation defaults will be specified jointly
  with Phase 3 before sensitive records. No platform or impersonated access.
- Physical NTAG/printer supplies, outside-provider terms, facilitator listing name,
  incident categories, parent notice defaults, award approval, pathway source and
  store/Firebase registrations need explicit recorded qualification. Independent
  code work continues while external evidence is unavailable.
- Application fees use recorded office payment until the Phase 5 gateway exists;
  cards do not gain payment rights in Phase 4. No provider/hardware spend here.
